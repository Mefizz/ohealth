# TV 3.17 — Electronic Service Requests («Електронні направлення»)

## Summary

Static, read-only audit of the primary workspace as of 2026-09-14. No tests or database operations were run.

The MIS has substantial ServiceRequest lifecycle plumbing: patient-context create/prequalify/sign APIs, local drafts, care-plan and encounter creation flows, requisition search, patient registry, signed recall/cancel, CODE128 printout, qualify-before-use for requests with a program, `used_by_employee`, and completion against linked EMR resources.

Compliance is nevertheless incomplete. The executor flow has no explicit ban preventing a `DOCTOR` from qualify/use of counselling referrals; no specimen-context workflow was found; no reuse-minute window is represented or enforced; qualify is skipped when no program is present; and completion has no program handling or remaining-quantity warning. Search also retains the complete remote result and places the subject UUID in rendered Livewire action markup, so impersonal/specimen-context disclosure is not demonstrably enforced.

Legend: ✅ implemented with direct evidence; ⚠️ partial or materially uncertain; ❌ not found / contradicted by code; ❓ cannot establish statically without the normative TV text or eHealth runtime.

## Gaps by priority

### P0

1. **DOCTOR can use counselling referrals.** Add a server-side employee-role/category gate before qualify and use, shared by Livewire, controller and encounter redemption. Do not rely on eHealth rejecting it.
2. **No specimen-context/impersonal workflow.** Implement the TV-prescribed specimen lookup/view path using `service_request:read_impersonal`, with a response projection that omits subject PII.
3. **Impersonal search disclosure is not contained.** Do not retain/render the raw eHealth ServiceRequest response; map only action-required fields. Avoid putting subject UUID into DOM action arguments where an opaque server-side key can be used.

### P1

1. **No reuse-minute enforcement.** Persist the authoritative use/cancel timestamps needed by TV and block re-use until the prescribed interval has elapsed; cover boundary times.
2. **Completion ignores program and has no remaining-quantity warning.** Define the exact complete payload/program rules and display the mandated warning before confirmation.
3. **Qualify is conditional on program.** Verify the TV/API contract and call qualify for all required use cases, with blocking behavior for invalid results.
4. **Draft editing is mostly navigation, not a proven update lifecycle.** Hydrate existing draft values, validate changes, persist them, and ensure sign uses the edited snapshot.

### P2

1. Verify custom printout fields/wording against the official TV template or consume the eHealth printout endpoint if required.
2. Add explicit inpatient ServiceRequest tests for allowed categories, incoming referral linkage, use and completion.
3. Expand search/filter coverage if TV requires criteria beyond requisition and local status/date filters.
4. Add tests for urgent priority end-to-end and for PII-free impersonal/specimen output.

## Test coverage observations

Existing tests cover payload mapping, create/sign, prequalify failure, recall/cancel, printout barcode, requisition search, API route permissions, ownership and EMR completion. Important absent cases are DOCTOR+counselling denial, `service_request:read_impersonal`, specimen context, raw subject-data projection, urgent executor behavior, reuse timing, program-aware completion, remaining-quantity warning, and true draft editing.

Some referral feature tests define `migrate:fresh` hooks (`tests/Feature/Referral/ReferralLifecycleTest.php:34-45`; `tests/Feature/Referral/ReferralExecutorPhase4Test.php:38-48`; `tests/Feature/Api/ReferralControllerTest.php:31-41`). They were not executed during this audit.
