# Independent mapping baselines

These expectations were captured before replacing each legacy implementation. They are not generated by the Symfony DTOs.

- `composition-baseline.json`: 14 create/cancellation cases captured from main `b70debf113ecfd4f06da167c57f50981d2f47e3f`, using the original Composition forms and BuildsCompositionPayload. Europe/Kyiv, `d.m.Y`, with explicit UTC cases in `composition-inputs.php`. Exact JSON uses `JSON_THROW_ON_ERROR | JSON_PRESERVE_ZERO_FRACTION`.
- `paper-referral-baseline.json`: nine outbound/hydration cases captured from main `b43c425ecc53738460e8e3c27fcef52952f6decf`, using the original PaperReferralMapper. Inputs include missing/null, false/zero, empty/missing EDRPOU, electronic/paper precedence and timestamp dates.
- `composition-form-baseline.json`: 20 refinement/continuation cases captured from the original CompositionTempDisabilityForm on both main `b43c425ecc53738460e8e3c27fcef52952f6decf` and published audit snapshot `979e534727111629ca5d952ab8aba86627b9a74d`, before replacing prefill methods. Both captures have SHA-256 `6e6c5cb9e2deb77049ba64adf87e0cc36ae1a2f4cc1c6c2ea55e994d2787026c`. Cases cover own/separate focus, patient identification, missing fields, explicit false, duplicate extensions, date formats and continuation resets.

The DTO tests exercise the actual form methods and both clinical parent mappers. Existing application helpers and API casing contracts are intentionally retained. The snapshots pin current behavior; they do not by themselves establish conformance to every ESOZ requirement or cover PostgreSQL persistence and real KEP.

Additional literal Extension cases verify that explicit false, string zero and empty string survive when that typed value is present. This does not change which optional flags the create form sends.
